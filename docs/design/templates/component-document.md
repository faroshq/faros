# Replace with the component name

Use this template for reusable component contracts. Keep each required section
in order and replace the example prose with evidence-backed guidance.

## Purpose

Describe the user need and responsibility of the component.

## Use when

Describe the situations in which this component is the right choice.

## Avoid when

Describe nearby cases that need a different pattern or primitive.

## Anatomy and variants

Describe the structure, slots, states, and supported variants.

## Behavior

Describe interaction, state transitions, loading, empty, and error behavior.

## Content

Describe labels, actions, messages, and content rules.

## Layout and responsive behavior

Describe geometry, spacing, breakpoints, and responsive changes.

## Accessibility

Describe semantics, keyboard behavior, focus, announcements, and contrast.
